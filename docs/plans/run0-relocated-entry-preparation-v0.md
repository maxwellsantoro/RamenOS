Source-derived preparation reviewed on 2026-10-06. The collector, profile and schema are not frozen; no capture or ownership transition has occurred. The accepted pure selector remains a numeric prerequisite, and the current UEFI path has no actual ownership transition. This preparation grants no native interface, kernel change or hardware actuation authority.

The smallest first packet is the existing external Oracle's three-checkpoint capture, with a bounded candidate-address admission rule. The next packet collects actual retained extents and the final successful firmware-exit map, masks interrupts, validates access, and installs the admitted pool once. ## Resolve the relocated entry without changing the guest

Choose a supplied **prior-run candidate** as a hint, not a receipt. The hint must reference an actual retained diagnostic from the exact pinned EFI, OVMF, machine/CPU and initial VARS/ESP profile. Freeze one candidate loaded base and entry address before the fresh VM's first resume. Do not scan RAM, try an address list, install a software breakpoint, patch the guest, disable relocation, insert a spin loop, rewrite registers or silently retry after a miss.

At reset-paused startup, install the candidate using the actual remote hardware-breakpoint operation and record its response. After resume, C0 must be an actual hardware stop at that exact address in the fresh run. Checked PE32+ AMD64/EFI-application parsing derives the entry RVA from the pinned input; derive `observed_loaded_base = actual_RIP - entry_RVA`, check complete image bounds and equality with the candidate base, and retain bounded loaded-header and entry-code bytes through the RAM-only reader. Validate the input section-to-file-offset relationship; an RVA is not a file offset. Compare the original entry instruction bytes with relocation-aware expected input bytes. The minimal v0 may reject unsupported relocation records intersecting inspected code rather than masking arbitrary differences. No guessed Rust `efi_main` symbol replaces the PE entry wrapper's ABI.

Bind this C0 stop to a unique input image through pinned read-only ESP/input provenance, observed PE headers and entry bytes. Header/code samples do not claim a hash of every live image byte. Capture actual RCX/RDX, CPL and paging state; resolve the public SystemTable→BootServices→GetMemoryMap chain with checked public layouts and signatures/size/CRC validation. The explicit ABI offsets derived from the pinned public raw crate must be independently checked against the spec before a decoder freeze; no transmutation of Rust-private objects. Firmware CRC checking is pure offline work, never an injected firmware call. This inspection supplies no authenticity claim beyond the pinned inputs and actual observed binding.

Then preserve C1/C2 exactly as the maintained Oracle contract: hardware breakpoint on the actual GetMemoryMap pointer, genuine EFI caller/return-site binding, five original pointers, entry capacity, successful return and returned scalars/raw map. The pinned crate has separate map-size-query and buffer-map helper paths (the current selected `memory_map` invokes the firmware function once); the assertion inventory must identify the actual pinned EFI call-site range, not accept an arbitrary firmware caller or quietly skip a failed selected call.

Operational viability is still unproven. Pinned EDK II source includes a debug-only load base/entry diagnostic during load, before StartImage invokes the entry. It does not establish that the installed OVMF build emits that diagnostic, identifies this EFI uniquely, or delivers it before entry. Same-run log polling followed by stop/breakpoint installation has a race and is not the chosen method. A prior-run hint removes that installation race but may miss if the fresh load address changes; preserve such a run as INCOMPLETE. An actual missed stop cannot become a synthetic C0. If no usable prior diagnostic exists, do not grow an automatic fallback. The alternative is a separate reviewed profile adding a pre-entry firmware discovery stop, with exact firmware symbols/instruction identity and bounded actual argument decoding; no such address or stop is available here.

## Exact current source gaps

* `kernel_uefi/src/main.rs:36` enters with BootServices active, loads init, calls the early map helper, runs probes, then enters `boot_main`. There is no `exit_boot_services` call. The early helper uses an 8192-byte stack buffer, maps BootServicesCode/Data to Usable, filters out all non-Usable descriptors and multiplies page counts without checked arithmetic. It cannot be the final map or retention basis.
* `load_init_image` knows the allocated page count but exports only pointer and bytes read. Its `size as usize`, page rounding and allocated-length multiplication require checked adapter admission; bytes read alone do not retain allocation slack. All file/protocol owners must end before exit.
* `InitImage` has only ptr/len. `BootMemoryMap` now has 256 descriptors and sticky overflow; its complete map capacity does not fix the converter's filtering.
* `boot_main` (boot.rs:399) gets CR3 and calls legacy `mm::init(map)` while still in firmware. `mm::init` picks the largest Usable range, rounds pages and overwrites the global Option; it only logs reservations. Its comment promises one-time initialization, but the current function does not enforce a second-install denial. New production installer must consume the validated pool and explicitly refuse replacement; it must not silently reuse this path.
* Current x86 MMU table access directly casts physical addresses to pointers. The new bounded reader needs a separately established initial identity/RAM-access precondition; using this walker to prove its own first dereference is circular. Current CR3 helper only masks the low 12 bits; the profile must first validate supported mode/physical width/modifiers.
* Pinned `uefi 0.27` exit consumes the Boot table, allocates final map as the requested type, performs at most two attempts and resets on unrecoverable failure. There is no `Result` to turn into an ordinary returned failure. No adapter outer retry or fake exit success is appropriate. The returned map privately stores capacity/stride/count and does not expose observed DescriptorVersion or complete allocation size; public entries are insufficient to reconstruct slack or arbitrary extension bytes. Preserve every final LoaderData descriptor and keep the map live. If production claims a parallel full raw stride/version byte record, root must resolve the actual public API gap with a reviewed adapter seam; do not transmute private layout or claim such a record already exists.

## Retention and handoff direction

All seven existing retention reasons remain mandatory. Derive byte extents from actual object ownership and translate them under the supported current CPU state; output the complete containing final non-Usable descriptor(s), never page-round an unproved pointer into ownership. Prove every byte covered across descriptor boundaries; overlapping reasons are allowed. Reject gaps, Conventional backing, lost descriptor counts and unsupported access. Keep a bounded parallel original type/attribute record; Reserved alone may denote MMIO.

| Reason | Actual source / retained extent |
|---|---|
| CurrentStack | Actual post-exit RSP and complete containing descriptor, plus a proven remaining-stack-use bound. If firmware stack headroom/lifetime cannot be established, root must freeze an explicit owned pre-exit stack and switch choreography before adapter implementation; one RSP sample is insufficient. |
| InitImage | Actual allocation base and checked complete pages×4096, with actual bytes read contained. Preserve all slack. |
| KernelImage | Before exit, current image Handle→LoadedImage::info base/size for the complete PE image containing kernel/static scratch/bitmap; scope-close the protocol before exit. After exit, translate complete extent and retain complete containing non-Usable descriptors. |
| PageTables | Actual CR3 root plus every reachable intermediate table under four-level paging; huge leaves are leaves. Complete bounded walk ≤256 frames, no recursive expansion, no cycle/incompatible-depth reuse; retain each whole 4096-byte frame's final descriptor coverage. |
| Gdt | Actual post-exit SGDT base and checked inclusive limit+1, complete translated extent, retained descriptor coverage. Does not claim an owned replacement GDT. |
| Idt | Actual post-exit SIDT base and checked inclusive limit+1; same complete coverage. Does not claim working interrupt/fault recovery. |
| FinalMapBuffer | Public actual final entries' backing plus every original LoaderData descriptor, including unobserved allocator header/slack; keep actual MemoryMap alive. No private-layout inference. |

Run existing GOP/IOMMU/NVMe/A-B/nonce probes before exit and retain their copied summaries; no arbitrary ACPI/GOP/MMIO dereferences afterward. Retaining a Runtime table value is not permission to call runtime services. Any later raw firmware-table consumer must return to root for explicit retention/accounting; it is not smuggled under one of the seven reasons.

Final conventional-only pool selection remains `[4096,0xc0000000)`, max 131072 frames, no firmware reclaim/coalescing/reset, all retention below4GiB for this profile. Validate effective identity+write coverage over every selected pool page before real allocation accesses. Runtime attribute prevents Usable classification. The pinned MemoryAttribute OR mask is `0xcffff000000ff01f`; preserve raw bits. Known capability bits do not prove active access permissions. Unknown/ISA-specific policy is an explicit supported-profile decision to freeze against archived primary definitions, not an invented corruption claim.

## Smallest ownership sequence and evidence splits

1. Root prepares source/EFI/symbols/init/firmware/tool/ESP pins and freezes the external profile, schema, address hint and transport assertions. Initial RED exercises validators/spies, not actual firmware claims.
2. Root executes one owned external capture after independent collector review. Offline decoder validates actual C0/C1/C2/RAM-only paging observations. Every broad claim remains false. Missing prerequisites/candidate/capability produce INCOMPLETE; malformed artifacts produce DENY; only actual recorded calls may supply observed data.
3. Freeze the distinct guest adapter API/assertions after those observations establish a supported initial-access design. The external snapshot does not establish future mapping continuity. The guest must validate actual CPU state/access assumptions again and preserve mappings/owned lifetimes through collection. Scratch is fixed image memory or a pre-exit LoaderData allocation accounted in final retention, never the future pool and never a 256-frame queue on an unbounded firmware stack.
4. Adapter completes all firmware work, obtains current LoadedImage and allocation extents, closes protocol/file owners, consumes `st.exit_boot_services(LOADER_DATA)` once, immediately masks interrupts and observes IF=0, then collects/validates the actual final map+all retention under bounded actual translations. It makes no subsequent firmware call. It passes a validated BootPool to a one-shot installer before other frame consumers.
5. Root QEMU gate checks real allocate/write/read/free/reuse, independent bounded temporary-allocator exhaustion and a subsequent unrelated consumer, unchanged init bytes, plus existing S8 data-plane behavior on the same handoff. Preserve actual source/binary/firmware/rawmap/retention/CPU/log hashes and actual owned VM lifecycle. A synthetic exit-failure fixture only proves no-install in its model; the crate's real reset-on-failure path remains separately scoped.
